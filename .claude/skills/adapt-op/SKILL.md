name: adapt-op
description: Analyze the CUDA kernel and automatically generate all integration code to make it a fully working operator in MyOps.
---

## What the user provides

The user writes a CUDA kernel `.cu` file (or tells you the path to one they already wrote). This kernel lives under `csrc/kernels/`.

## What you must do

### Step 1: Analyze the kernel

Read the `.cu` file and determine:
- **Op name**: extract from function names / file name
- **Op category**: unary element-wise, binary element-wise, or custom (e.g. matmul, reduce, etc.)
- **Input/output signature**: how many inputs, how many outputs, what shapes
- **Launch function signature**: what parameters `launchXxxKernel()` takes
- **Supported dtypes**: look for template types, dtype switches (float/half/bfloat16)
- **Whether it fits the element-wise framework** (uses `launch_vectorized_kernel` + `TensorArray`) or needs a custom adapter
- **Whether the `launchXxxKernel` (MyOpsDtype dispatch) function exists**: the user may only provide `__global__` kernel + `launchXxxKernelImpl` template function, without the outer `launchXxxKernel` that switches on `MyOpsDtype` and casts pointers

### Step 2: Update C++ integration files

Based on the category:

#### If element-wise unary (fits `FOR_EACH_UNARY_OP` framework):
1. **`csrc/include/unary_ops.cuh`** — Add the op implementation for all 3 dtype specializations (float, `__half`, `__nv_bfloat16`) inside `UnaryOps<T>` and its template specializations
2. **`csrc/include/kernels.h`** — Add entry to `FOR_EACH_UNARY_OP` macro list: `_(op_name, OpName)`
3. Everything else (kernel dispatch, torch_api adapter, register.cpp) is auto-generated by existing macros — no changes needed

#### If element-wise binary (fits `FOR_EACH_BINARY_OP` framework):
1. **`csrc/include/binary_ops.cuh`** — Add the op implementation for all 3 dtype specializations
2. **`csrc/include/kernels.h`** — Add entry to `FOR_EACH_BINARY_OP` macro list: `_(op_name, OpName)`
3. Everything else is auto-generated — no changes needed

#### If custom/standalone op:
1. **`csrc/include/kernels.h`** — Declare the launch function:
   ```cpp
   void launchOpNameKernel(void* out, const void* input, <other_params>, cudaStream_t stream, MyOpsDtype dtype);
   ```
2. **`csrc/torch_api/torch_api.h`** — Declare the adapter function:
   ```cpp
   void op_name(const at::Tensor& input, at::Tensor& out);
   ```
3. **`csrc/torch_api/register.cpp`** — Add two lines:
   - Schema: `m.def(TORCH_SELECTIVE_SCHEMA("myops::op_name(Tensor input, Tensor(a!) out) -> ()"));`
   - Impl: `m.impl(TORCH_SELECTIVE_NAME("myops::op_name"), TORCH_FN(op_name));`
   Adjust schema based on actual signature (e.g., binary ops have 2 input tensors).
4. **`csrc/torch_api/<op_name>.cpp`** — Create adapter implementing:
   - Input validation (`checkTensorContiguous`, `checkTensorSameAttr`)
   - Dimension/shape checks as needed
   - Dtype conversion via `scalarTypeToMyOpsDtype()`
   - Stream acquisition via `at::cuda::getCurrentCUDAStream()`
   - Device guard
   - Kernel launch call
   Follow the pattern of `matmul.cpp` for custom ops.

**If the `.cu` file does NOT contain the `launchXxxKernel` (MyOpsDtype dispatch) function**, you must generate it inside the `.cu` file. This function is the C-style entry point declared in `kernels.h` and called by the torch_api adapter. It switches on `MyOpsDtype` and calls the template `launchXxxKernelImpl` with the appropriate cast. Pattern:

```cpp
void launchOpNameKernel(void *output, const void *input, <other_params>,
                        cudaStream_t stream, MyOpsDtype dtype) {
  switch (dtype) {
    case MYOPS_DTYPE_FLOAT:
      launchOpNameKernelImpl(static_cast<float *>(output), static_cast<const float *>(input), <other_params>, stream);
      break;
    case MYOPS_DTYPE_HALF:
      launchOpNameKernelImpl(static_cast<__half *>(output), static_cast<const __half *>(input), <other_params>, stream);
      break;
    case MYOPS_DTYPE_BFLOAT16:
      launchOpNameKernelImpl(static_cast<__nv_bfloat16 *>(output), static_cast<const __nv_bfloat16 *>(input), <other_params>, stream);
      break;
    default:
      MYOPS_CHECK_FAILED("Only support float32, bfloat16 and half.");
  }
}
```

Important rules for generating the dispatch function:
- Must be inside `namespace myops { }`
- Pointer params use `void*` for output, `const void*` for inputs
- Scalar/integer params pass through unchanged
- `cudaStream_t` and `MyOpsDtype` are always the last two params
- Cast `void*` → `float*/__half*/__nv_bfloat16*` and `const void*` → `const float*/const __half*/const __nv_bfloat16*`
- If the `Impl` function takes `const void*` instead of typed pointers, adjust casts accordingly

### Step 3: Update Python API

**`myops/ops.py`**:
- Add the op name to `__all__` list
- For unary ops: `op_name = _make_unary_op("op_name")`
- For binary ops: `op_name = _make_binary_op("op_name")`
- For custom ops: write a dedicated wrapper function following the `matmul` pattern (auto-allocate output if `out is None`, call `torch.ops.myops.op_name(...)`, return output)

### Step 4: Write tests

Create **`tests/test_<op_name>.py`** following this pattern:

```python
import torch
import pytest
from myops import op_name

# Determine reference torch function
# unary: torch.op_name or torch.nn.functional.op_name
# binary: torch.op_name
# custom: implement reference manually

@pytest.mark.parametrize("shape", [
    (16,), (1024,), (1024 * 1024,),
    # for 2D ops: (16, 16), (128, 256), etc.
])
@pytest.mark.parametrize("dtype", [torch.float32, torch.float16, torch.bfloat16])
def test_op_name_correctness(shape, dtype):
    # Generate input data
    input = torch.randn(shape, dtype=dtype, device="cuda")
    # For binary ops, also generate second input

    result = op_name(input)
    expected = torch_ref_func(input)  # reference implementation
    assert torch.allclose(result, expected, rtol=1e-3, atol=1e-4)

def test_op_name_out_parameter():
    input = torch.randn(1024, dtype=torch.float32, device="cuda")
    out = torch.empty_like(input)
    result = op_name(input, out=out)
    assert result is out  # should return same tensor

# Edge cases per op type:
# - For ops with domain restrictions (log, div): test with valid-range inputs
# - For reduction/matmul: test non-aligned sizes, edge-case dims
# - Always test that out-of-place and in-place (with out=) produce same result

if __name__ == "__main__":
    pytest.main([__file__, "-v"])
```

**Key rules for tests**:
- Use `@pytest.mark.parametrize` for shapes and dtypes
- Compare against torch reference (e.g., `torch.add`, `torch.abs`, `torch.matmul`)
- For fp16/bf16, use looser tolerance: `rtol=1e-2, atol=1e-3`
- For fp32, use `rtol=1e-3, atol=1e-4`
- Test the `out=` parameter path
- Import from `myops` top-level, not internal modules

### Step 5: Write benchmark

Create **`benchmark/benchmark_<op_name>.py`** following this pattern:

```python
import torch
from tabulate import tabulate
from common import benchmark_kernel
from myops import op_name

params = [
    # Small
    {"shape": (1024,), "dtype": torch.float32},
    # Medium
    {"shape": (1024 * 1024,), "dtype": torch.float32},
    # Large
    {"shape": (1024 * 1024 * 10,), "dtype": torch.float32},
    # Add fp16/bf16 variants
    {"shape": (1024 * 1024,), "dtype": torch.float16},
    {"shape": (1024 * 1024,), "dtype": torch.bfloat16},
]

def main():
    all_results = []
    for p in params:
        shape, dtype = p["shape"], p["dtype"]
        # Generate inputs
        input = torch.randn(shape, dtype=dtype, device="cuda")
        # For binary: also generate second input

        # Benchmark torch reference
        torch_time = benchmark_kernel(torch_ref_func, (input,), repeats=100)
        # Benchmark myops
        myops_time = benchmark_kernel(op_name, (input,), repeats=100)

        speedup = torch_time / myops_time if myops_time > 0 else float("inf")
        all_results.append({
            "shape": shape, "dtype": dtype,
            "torch_ms": torch_time, "myops_ms": myops_time,
            "speedup": speedup,
        })

    table_data = []
    for r in all_results:
        dtype_str = str(r["dtype"]).split(".")[-1]
        table_data.append([
            str(r["shape"]), dtype_str,
            f"{r['torch_ms']:.3f}", f"{r['myops_ms']:.3f}",
            f"{r['speedup']:.2f}x",
        ])
    headers = ["Shape", "Dtype", "torch (ms)", "myops (ms)", "Speedup"]
    print(tabulate(table_data, headers=headers, tablefmt="grid", floatfmt=".3f"))

if __name__ == "__main__":
    main()
```

**Key rules for benchmarks**:
- Import `benchmark_kernel` from `benchmark.common`
- Use `tabulate` for formatted output
- Compare against torch reference
- Test multiple sizes (small/medium/large) and all supported dtypes
- `repeats=100` for stable timing

### Step 6: Build and verify

#### If use provides the implementation of kernel, then  do the following things：

1. Run `pip install -e .` to rebuild the C++ extension
2. Run the test: `python -m pytest tests/test_<op_name>.py -v`
3. If test fails, debug and fix
4. Report completion with a summary of all files changed/created

#### If use NOT provides the implementation of kernel, then do nothing

## Important notes

- Do **NOT** provides the implementation of kernel
- The `registry.py` and `run.py` mechanism is **deprecated** — do NOT update them
- The `myops/triton/` directory is for Triton reference implementations — do NOT modify unless asked
- Always follow existing code patterns and naming conventions
- The `csrc/kernels/<op>.cu` file is provided by the user — do NOT modify it unless there's a clear bug
- For dtype support: all ops should support fp32, fp16, bf16 unless the kernel explicitly doesn't
- When writing the torch_api adapter for custom ops, always include: contiguous check, same-attr check, dtype conversion, stream acquisition, device guard
- The kernel launch function in `kernels.h` must use `void*` for pointers and `MyOpsDtype` for dtype (matching the C dispatch pattern in existing kernels)

## Checklist summary

For each new op, verify:
- [ ] `csrc/include/kernels.h` — launch function declared (custom) or macro updated (element-wise)
- [ ] `csrc/include/<op_type>_ops.cuh` — op implementation added (element-wise only)
- [ ] `csrc/torch_api/torch_api.h` — adapter function declared (custom only)
- [ ] `csrc/torch_api/register.cpp` — schema + impl registered (custom only)
- [ ] `csrc/torch_api/<op>.cpp` — adapter implemented (custom only)
- [ ] `myops/ops.py` — Python wrapper added + `__all__` updated
- [ ] `tests/test_<op>.py` — correctness tests written
- [ ] `benchmark/benchmark_<op>.py` — benchmark script written
