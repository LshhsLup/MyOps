# MyOps - CUDA Operator Development Framework

## Project Overview

MyOps is a custom CUDA operator library for PyTorch, supporting fp32/fp16/bf16. Operators are written as CUDA kernels and exposed to Python via PyTorch's C++ extension / `torch.library` mechanism.

## Architecture

```
csrc/
  include/          # Shared headers (common.h, kernels.h, element_wise.cuh, *_ops.cuh)
  kernels/          # CUDA kernel implementations (.cu files)
  torch_api/        # C++ adapter layer binding CUDA kernels to PyTorch tensors
                     #   register.cpp  - TORCH_LIBRARY schema + impl registration
                     #   utils.h       - tensor checks, dtype conversion helpers
                     #   <op>.cpp      - per-category adapter (matmul.cpp, unary.cpp, binary.cpp)
myops/
  __init__.py       # imports _core + ops
  ops.py            # Python API: wraps torch.ops.myops.* with ergonomic signatures (auto-allocate out)
  cuda/__init__.py  # re-exports from ops (for myops.cuda.xxx usage)
  triton/           # Triton reference implementations (separate from CUDA flow)
tests/              # pytest tests per operator
benchmark/          # Benchmark scripts per operator
```

## Operator Categories

### Element-wise Unary Ops (abs, neg, exp, log, relu, sigmoid)
- **Ops traits**: `csrc/include/unary_ops.cuh` — `UnaryOps<T>::name(T x)` per dtype
- **Kernel dispatch**: `csrc/kernels/unary.cu` — functor + `launch_vectorized_kernel` + dtype switch
- **Torch adapter**: `csrc/torch_api/unary.cpp` — macro `DEFINE_UNARY_OP` generates `void name(Tensor input, Tensor out)`
- **kernels.h**: `FOR_EACH_UNARY_OP` macro list + `DECLARE_UNARY_KERNEL` macro
- **Python API**: `myops/ops.py` — `_make_unary_op(name)` factory

### Element-wise Binary Ops (add, sub, mul, div)
- Same pattern as unary but with 2 inputs. See `binary_ops.cuh`, `binary.cu`, `binary.cpp`
- **Python API**: `_make_binary_op(name)` factory

### Custom Ops (e.g., matmul)
- Standalone kernel in `csrc/kernels/matmul.cu`
- Manual adapter in `csrc/torch_api/matmul.cpp`
- Manual Python wrapper in `myops/ops.py`

## Adding a New CUDA Operator — Full Pipeline

When a developer writes a new `.cu` kernel, the following files must be updated to integrate it:

1. **`csrc/include/kernels.h`** — Declare `launchXxxKernel()` function
2. **`csrc/kernels/<op>.cu`** — Kernel implementation (provided by developer)
3. **`csrc/torch_api/torch_api.h`** — Declare the torch_api function signature
4. **`csrc/torch_api/register.cpp`** — Add `m.def(...)` schema + `m.impl(...)` registration
5. **`csrc/torch_api/<op>.cpp`** — Implement the adapter (checks, dtype dispatch, kernel launch)
6. **`myops/ops.py`** — Add Python wrapper function + `__all__` entry
7. **`tests/test_<op>.py`** — pytest with parametrized shapes/dtypes, correctness check vs torch reference
8. **`benchmark/benchmark_<op>.py`** — Benchmark vs torch baseline using `benchmark_kernel` from `common.py`
9. **Build & verify** — `pip install -e .` then run tests

### For element-wise ops that fit the existing framework (unary/binary):
- Just add the op name to `FOR_EACH_UNARY_OP` / `FOR_EACH_BINARY_OP` in `kernels.h`
- Add the op implementation in `unary_ops.cuh` / `binary_ops.cuh`
- Everything else is auto-generated by macros

### For standalone/custom ops:
- Create new `.cu`, new `.cpp` adapter, new Python wrapper, new test, new benchmark

## Supported Dtypes

`float32`, `float16` (`__half`), `bfloat16` (`__nv_bfloat16`) — mapped via `MyOpsDtype` enum and `scalarTypeToMyOpsDtype()`.

## Code Style

- CUDA: C++17, `myops` namespace, `MYOPS_*` macros for launch bounds/checks
- Python: type hints, `__all__` exports, pytest parametrize
- No comments unless WHY is non-obvious
