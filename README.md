# MyOps

> For Learning & Practice Only - This is a personal project for studying CUDA kernel development.

A high-performance CUDA operator library for PyTorch, with vectorized element-wise kernel framework and multi-dtype support (fp32/fp16/bf16).

## Features

- **PyTorch Integration**: Seamless access via `torch.ops.myops` and `torch.library`

## Requirements

- CUDA Toolkit 11.0+
- PyTorch with CUDA support (>= 2.0)
- Python 3.8+

## Installation

```bash
pip install -e .
```

## Usage

### Python API

```python
import myops

# Unary operators
y = myops.abs(x)
y = myops.neg(x)
y = myops.exp(x)
y = myops.log(x)
y = myops.relu(x)
y = myops.sigmoid(x)

# Binary operators
c = myops.add(a, b)
c = myops.sub(a, b)
c = myops.mul(a, b)
c = myops.div(a, b)

# Matrix multiplication
c = myops.matmul(a, b)

# With explicit output tensor
out = torch.empty_like(x)
myops.abs(x, out=out)
```

## Adding a New Operator

### Quick way: `adapt-op` skill

Write your CUDA kernel in `csrc/kernels/`, then tell Claude Code to adapt it:

```
please help me adapt csrc/kernels/your_new_kernel.cu
```

Claude Code has an `adapt-op` skill (`.claude/skills/adapt-op.md`) that will automatically:
1. Analyze your kernel (category, signature, dtypes)
2. Update C++ integration files (kernels.h, torch_api adapter, register.cpp)
3. Add Python wrapper to `myops/ops.py`
4. Generate `tests/test_<op>.py` with parametrized correctness tests
5. Generate `benchmark/benchmark_<op>.py` with torch baseline comparison
6. Build and verify

### Manual way

#### For element-wise unary/binary ops (fits macro framework)

1. Add op implementation in `csrc/include/unary_ops.cuh` or `binary_ops.cuh` (all 3 dtype specializations)
2. Add entry to `FOR_EACH_UNARY_OP` or `FOR_EACH_BINARY_OP` macro in `csrc/include/kernels.h`:
   ```cpp
   _(your_op, YourOp)
   ```
3. Add Python wrapper in `myops/ops.py`:
   ```python
   your_op = _make_unary_op("your_op")  # or _make_binary_op
   ```
4. Add `your_op` to `__all__`
5. Write tests and benchmarks
6. `pip install -e .` && `pytest`

Everything else (kernel dispatch, torch_api adapter, registration) is auto-generated by the macro framework.

#### For custom/standalone ops

1. **`csrc/include/kernels.h`** — Declare launch function
2. **`csrc/torch_api/torch_api.h`** — Declare adapter function
3. **`csrc/torch_api/register.cpp`** — Add schema + impl
4. **`csrc/torch_api/<op>.cpp`** — Implement adapter (checks, dtype dispatch, kernel launch)
5. **`myops/ops.py`** — Add Python wrapper + `__all__`
6. Write tests and benchmarks
7. `pip install -e .` && `pytest`

Follow the `matmul` pattern for reference.

## Architecture Notes

- **Supported GPUs**: Volta (sm_70) through Hopper (sm_90)
